# MSC00-F. Compile cleanly at high warning levels

Compile code using the highest warning level available for your compiler and eliminate warnings by modifying the code.

According to the \[ [Fortran Standard (subclause 4.2, *Conformance* [ISO/IEC 1539-1:2018])](/sei-cert-fortran-coding-standard/back-matter/aa-bibliography#AA.Bibliography-Fortran2018) \], a Fortran compiler is not required to diagnose every violation that can lead to erroneous or undefined program behavior: 

> [...]
> 
> **(2)** it contains the capability to detect and report the use within a submitted program unit of a form designated herein as obsolescent, insofar as such use can be detected by reference to the numbered syntax rules and constraints;
> 
> **(3)** it contains the capability to detect and report the use within a submitted program unit of a form or relationship that is not permitted by the numbered syntax rules or constraints, including the deleted features described in Annex B;
> 
> [...]

Compiler warnings provide capabilities to that can identify programming errors in Fortran code, such as implicit or inconsistent procedure interfaces, questionable argument association, possible aliasing, implicit conversions that may change a value, unused entities, suspicious control flow, line truncation, use of nonstandard language extensions, and other constructs that are likely to indicate programming errors.

> **Tip**
> 
> Eliminating compiler warnings does not guarantee that a program conforms to the Fortran standard or is free of defects. Different compilers and static analysis tools can provide different diagnostics and should be used where available.


The following table shows recommended compiler options for the GNU `gfortran` and LLVM `flang` compilers. The availability and precise behavior of diagnostic options are compiler- and version-dependent.

| Compiler   | Recommended options | Purpose  |
|------------|---------------------|----------|
| `gfortran` | `-Wall` `-Wextra` `-Wpedantic` | Enable commonly useful warnings, additional diagnostics, warnings for nonstandard extensions. |
|            | `-Wimplicit-interface` `-Wimplicit-procedure` `-Wconversion-extra` | Turn on Fortran-specific warning (e.g. , missing explicit interfaces, implicitly declared procedures, additional implicit conversions). |
|            | `-Werror`.  | Turn all warnings into errors, causing compilation to fail when a warning is emitted. |
| `flang`    | `-pedantic` | Warn about language extensions. |
|            | `-Werror`   | Turn warnings into errors, causing compilation to fail when a warning is emitted. |


## Noncompliant Code Example (Non-Integer Loop Variable)

In this noncompliant example, the `DO` construct uses a variable of type `REAL` as its loop variable. The use of a `REAL` variable as the `DO` variable is a deleted Fortran feature. Compilers can continue to support deleted features as extensions, so the program might still compile unless appropriate diagnostic options are enabled.

::code-block{quality="bad"}
``` fortran
program main
  implicit none

  real :: i

  do i = 1.0, 3.0
    print *, i
  end do
end program main
```
::

## Compliant Code Example (Non-Integer Loop Variable)

The issue can be eliminated by declaring the `DO` variable as `INTEGER` and using integer initial, limit, and step expressions. This code uses the standard integer form of the `DO` construct.

::code-block{quality="good"}
``` fortran
program main
  implicit none

  integer :: i

  do i = 1, 3
    print *, i
  end do
end program main
```
::


## Risk Assessment

Compiler diagnostics can expose defects that lead to incorrect computation, undefined or otherwise nonconforming behavior, portability problems, and security vulnerabilities. Compiling cleanly with strong diagnostics reduces the likelihood that such defects remain undetected, but it does not replace code review, static analysis, testing, or compliance with the other guidelines in this coding standard.

| Guideline | Severity | Likelihood | Detectable | Repairable | Priority | Level  |
|-----------|----------|------------|------------|------------|----------|--------|
| MSC00-F   | Medium   | Likely     | Yes        | No         | **P4**   | **L3** |
