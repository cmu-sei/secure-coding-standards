# Introduction

This standard provides guidelines for secure coding in the Fortran programming language. The goal of these guidelines is to develop safe, reliable, and secure systems, for example by eliminating undefined behaviors that can lead to undefined program behaviors and exploitable vulnerabilities. Conformance to the coding guidelines defined in this standard are necessary (but not sufficient) to ensure the safety, reliability, and security of software systems developed in the Fortran programming language. It is also necessary, for example, to have a safe and secure design. However, the application of this coding standard will result in high-quality systems that are reliable, robust, and resistant to attack.

Each guideline consists of a *title* , a *description* , and *noncompliant code examples* and *compliant solutions* . The title is a concise, but sometimes imprecise, description of the guideline. The description specifies the normative requirements of the guideline. The noncompliant code examples are examples of code that would constitute a violation of the guideline. The accompanying compliant solutions demonstrate equivalent code that does not violate the guideline or any other guidelines in this coding standard.

A well-documented and enforceable coding standard is an essential element of coding in the Fortran programming language. Coding standards encourage programmers to follow a uniform set of guidelines determined by the requirements of the project and organization rather than by the programmers’ individual preferences. Once established, these standards can be used as a metric to evaluate source code (using manual or automated processes).

These pages contain ongoing updates of the standard between official published releases. For questions and comments about these standards, open a GitHub issue. For anything else, please [submit feedback](https://www.sei.cmu.edu/contact-us/).
